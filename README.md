# phoU — 사진 공유 앱 워킹 프로토타입 (팀 광명)

모임·여행 뒤 쌓인 사진을 **AI 추천으로 고르고**, 친구와 원본 화질로 나누는 앱의 워킹 프로토타입.
4주차 PRD와 Lo-Fi 6개 화면을 넣어 바이브 코딩으로 만들었다.

- **배포 주소**: https://diane-82.github.io/photo-share-app/
- **레포 주소**: https://github.com/diane-82/photo-share-app

## 실행 방법
- 배포 주소에 들어가서 "흐름 골라서 해 보기" 중 하나를 누른다.
- 로컬: 레포를 내려받아 `index.html`을 브라우저로 연다. 설치할 것 없음.
- 테스트 참가자가 바뀔 때는 첫 화면의 **테스트 데이터 지우기**를 누른다.

## 화면 구성
| 흐름 | 화면 | Lo-Fi |
|---|---|---|
| ① 보내는 사람 | 홈 → 앨범 만들기 → 공유 옵션 → QR·링크 보내기 → 홈(NEW) | 05 → 01 → 02 → 03 |
| ② 받는 친구 | 초대 확인 → 참여하기 → 공유된 앨범 → 사진 크게 보기 | 03 → 06 |
| ③ AI 추천 | 공유된 앨범 → AI 추천 확인 → 내 폰에 저장(비슷한 사진은 베스트 1장만) | 06 → 04 |

자세한 결정 사항은 [`docs/FLOW.md`](docs/FLOW.md), 단계별 기록은 [`docs/ai-log.md`](docs/ai-log.md).

## 사용한 툴
- **Claude Code** (Claude 데스크톱 앱 Code 탭) — 화면 생성·수정·검증, git 커밋
- **Claude** (웹) — 아이디어 정리, 첫 검증 화면(스와이프 선택) 생성
- **GitHub Desktop** — GitHub로 올리기(push)
- **GitHub Pages** — 배포
- 기술: HTML + CSS + Vanilla JS, 화면당 파일 하나, 외부 라이브러리 없음

## 핵심 프롬프트 (효과 있었던 것)
1. **규칙 파일(`AGENTS.md`)로 공통 규칙 고정** — 색·글자 크기·금지 사항을 매번 붙여넣지 않아도 모든 화면이 같은 톤으로 나옴. Claude Code용 `CLAUDE.md`는 `@AGENTS.md` 한 줄만.
2. **한 번에 한 화면 + 상태 3가지 명시** — "로딩 / 빈 상태 / 완료(또는 오류)"를 적으면 실제로 다 만들어짐. 적지 않은 상태는 나오지 않음.
   ```
   phoU 앱의 '앨범 만들기' 화면 하나만 만들어줘. (규칙은 AGENTS.md)
   · 사용자: 모임·여행 직후 친구들과 공유 앨범을 만들려는 사람
   · 화면 요소 (로우파이 01 4번째 스케치): …
   · 상태: 기본 / 입력 오류(종료일 < 시작일) / 완료(로딩 후 다음 화면)
   · 하지 말 것: 공유 옵션은 2차 화면이니 넣지 마.
   지금은 이 화면만 만들고 이후 과정 결정할게. 다른 화면은 만들지 마.
   ```
3. **"하지 말 것"을 따로 적기** — 삭제 기능, 로그인 화면, 외부 QR 라이브러리처럼 AI가 알아서 넣을 만한 것을 막음.
4. **화면마다 수용 기준을 먼저 정하고 그걸로 검증** — "연타해도 앨범 1개", "375px에서 안 잘림" 같은 기준이 있어서 고칠 점을 구체적으로 말할 수 있었음.
5. **참고 앱 스크린샷을 보여주기** — 색 코드를 말로 설명하는 것보다 Clutter 앱 화면을 보여준 게 원하는 톤에 훨씬 빨리 도달.
6. **예외도 규칙으로 남기기** — 공유 버튼 로고만 브랜드 색을 쓰기로 하고 `AGENTS.md`에 "예외" 한 줄 추가 → AI가 나중에 "그라데이션 금지"를 이유로 되돌리지 않게.

## 실패한 시도와 이유
| 시도 | 무엇이 잘못됐나 | 어떻게 바꿨나 |
|---|---|---|
| 첫 검증 화면 "스와이프 선택" (`screens/swipe-select.html`) | 화면 목적을 "보낼 사진 고르기"로 잘못 전달 → 실제 의도는 "이미 공유된 사진 중 저장할 것 고르기" | 프롬프트 첫 줄에 화면 목적을 한 문장으로 적음. 이 화면은 기록용으로 남겨 둠 |
| 강조색 핑크(#E8879A) | 흰 글씨 대비가 약하고, 참고한 앱 톤과 안 맞음 | 미니멀 흑백으로 변경 |
| 보조 텍스트 회색 #8C8C8C | 흰 배경 명도대비 3.4:1 → 체크리스트 기준(4.5:1) 미달 | #6B6B6B(최저 4.80:1)로 수정, 규칙 파일에 기록 |
| GitHub 웹에서 파일 업로드 | 폴더 위치가 틀어지고, 올릴 때마다 "Add files via upload" 커밋 하나만 남음 | GitHub Desktop 연결, 작업 단위 커밋(feat/fix/docs) |
| 새로 만든 앨범의 날짜 | 더미는 `date`, 새 앨범은 `start`로 저장해서 화면 읽기에서 "undefined"로 읽힘 | 날짜 형식을 맞추는 함수 하나로 통일 |
| 화면 수정 후 테스트 | 브라우저가 예전 파일을 기억(캐시)해서 바뀐 화면이 안 보임 | 캐시를 끄는 미리보기 서버로 다시 띄움 |
| 스크립트로 복사 버튼 테스트 | 브라우저 보안상 사람이 직접 누르지 않으면 복사가 안 됨 | 실제 클릭으로 다시 확인 |
| AI가 만든 문구 | 14px 글씨(규칙 위반), "AI 필터은" 같은 조사 오류, "올려/요" 같은 어색한 줄바꿈 | 화면마다 캡처로 확인하고 고침 |

## 검증 체크리스트 결과 (5주차 워크숍)
| 항목 | 결과 |
|---|---|
| 빈 상태 / 로딩 / 에러 화면이 실제로 나오는가 | 통과 — 화면마다 확인, 캡처는 `docs/screenshots/` |
| 새로고침하면 입력한 데이터가 사라지는가 | 사라지지 않음 — 만든 앨범은 브라우저에 저장(localStorage) |
| 버튼을 두 번 빠르게 누르면 | 통과 — 만들기·참여하기·저장 3연타해도 1번만 처리 |
| 모바일 폭(375px)에서 잘리는 곳 | 없음 |
| 키보드 Tab만으로 모든 기능에 닿는가 | 통과 — 화면마다 Tab 순서 확인, 크게 보기는 ←/→/Esc |
| 본문 명도대비 4.5:1 이상 | 통과 — 최저 4.80:1 |
| 색만으로 정보를 구분하지 않는가 | 통과 — 오류는 아이콘+문구+굵은 테두리, 선택은 채움+글자 |
| 이미지 대체 텍스트 | 통과 — 사진·QR·아이콘 버튼에 설명 |
| API 키가 코드에 있는가 | 없음 (서버·API 안 씀) |
| 실제 사람 이름·연락처를 더미로 썼는가 | 안 씀 — 이니셜(나, A~E)만 |
| AI 없이 색 하나를 바꿀 수 있는가 | 가능 — 각 파일 맨 위 `:root` 변수 한 곳 |
| 한 곳을 고치려면 몇 군데를 같이 고쳐야 하는가 | **미흡** — 아래 "남은 한계" 1번 |

## 남은 한계 / 다음 개선 포인트
1. **같은 코드가 화면마다 반복됨** — 디자인 토큰, 더미 앨범·사진 데이터, 탭바가 파일마다 복사돼 있어 색이나 더미 데이터를 바꾸려면 여러 파일을 고쳐야 함. 다음 단계에서 공통 CSS·JS 파일로 분리.
2. **받는 사람 웹 간소화 버전 없음** — PRD상 받는 친구는 웹에서 올리기·내려받기만 하지만, 지금은 앱의 공유된 앨범 화면으로 연결.
3. **AI 추천은 흉내** — 실제 AI가 아니라 "비슷한 사진 묶음의 첫 장"을 고르는 규칙. 추천 이유 배지도 더미.
4. **QR은 모양만** — 스캔 안 됨.
5. **3차 차별 기능은 안내만** — AI 필터, 비슷한 사진 정리 화면, 장소별 보기, "친구들이 사진을 올렸어요" 알림, 내 정보 탭.
6. **데이터는 한 브라우저에만** — 다른 기기에서 같은 앨범을 볼 수 없음(서버 없음).

## AI 활용 표시
- 화면 코드는 전부 Claude Code가 생성했고, 팀은 프롬프트·수용 기준·판단(받아들임/고침/버림)을 맡았다. 단계별 판단은 `docs/ai-log.md`에 기록.
- 커밋 중 AI가 작성한 것에는 `Co-Authored-By: Claude`가 붙어 있다.
- 카카오톡·인스타그램 로고는 서비스를 알아보게 하려는 프로토타입 용도로 단순화해 다시 그림(상표권은 각 회사). 디자인 톤은 Clutter 앱을 참고했지만 로고·일러스트·문구는 가져오지 않음.
