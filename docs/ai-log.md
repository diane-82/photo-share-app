# AI 활용 기록

> 작업 단계가 끝날 때마다 한 칸 추가. 개인 Figma 프레임 한 장 = 아래 기록 하나.
> README의 "핵심 프롬프트"와 "실패한 시도"도 여기서 옮긴다.
> 판단 칸이 계속 "그대로 사용"이면, 그대로 쓴 이유도 한 줄 적는다.

## 템플릿
### [날짜] 단계 이름
1. **단계와 목표**: 이번 단계에서 만들려던 것 / 수용 기준
2. **AI 활용 내역**: 도구 / 핵심 프롬프트 / 결과 캡처(`docs/screenshots/`)
3. **판단**: 받아들인 것 · 고친 것 · 버린 것과 이유
4. **검증**: 무엇으로 확인했는지 (검증 체크리스트 항목, 직접 테스트)
5. **윤리 점검**: 개인정보 · 저작권 · 출처 표기 · AI가 만든 부분 표시

### [2026-10 4~5주차] 1차 검증 — 스와이프 선택 화면
1. **단계와 목표**: 바이브 코딩으로 화면 하나가 실제로 동작하는지 확인
2. **AI 활용 내역**: Claude(웹) / PROJECT RULES + "스와이프 선택 화면 하나만" / `screens/swipe-select.html`
3. **판단**: 고친 것 — 화면 의미를 처음에 잘못 전달함(보낼 사진 고르기 → 이미 공유된 사진 중 저장할 것 고르기). 화면 목적을 한 줄로 먼저 적어야 한다는 걸 배움
4. **검증**: 직접 드래그·버튼 테스트, 세 상태 확인
5. **윤리 점검**: 더미 색 카드만 사용, 실제 사진·이름 없음. 코드 전체 AI 생성

### [2026-10-10] 세팅 — 맥락 이전과 플로우 정리
1. **단계와 목표**: 웹 대화 맥락을 Claude Code로 옮기고, 유저 플로우와 로우파이 맞추기
2. **AI 활용 내역**: Claude Code(데스크톱) / 인수인계 노트 + 4주차 PPT 대조
3. **판단**: 받아들인 것 — 플로우·로우파이 불일치 지적 중 홈 위치, 삭제 권한. 고친 것 — 화면 번호는 앱/웹 기준으로 나눈 의도라 유지. 버린 것 — 04의 "내 사진 모아보기"(06과 중복)
4. **검증**: 결정 사항을 `docs/FLOW.md`에 기록
5. **윤리 점검**: 예산·대화 내용이 담긴 인수인계 노트는 공개 레포에서 제외

### [2026-10-10] 디자인 방향 변경
1. **단계와 목표**: 앱 전체 톤 결정
2. **AI 활용 내역**: Clutter 앱 스크린샷을 참고 자료로 제공
3. **판단**: 고친 것 — 강조색 핑크(#E8879A) → 미니멀 흑백. 고친 것 — AI가 제안한 보조 텍스트 #8C8C8C가 대비 3.4:1이라 #6B6B6B로 수정
4. **검증**: 명도대비 계산(검증 체크리스트 2-접근성)
5. **윤리 점검**: Clutter는 레이아웃·톤 참고만, 로고·일러스트·문구는 가져오지 않음

### [2026-10-10] 홈 화면 v1 (워크숍 Step 2 → 첫 결과)
1. **단계와 목표**: 홈 화면 하나. 수용 기준 — 세 상태 동작 / 375px에서 안 잘림 / Tab 키로 모든 버튼 도달 / 대비 4.5:1 이상·이모지·그라데이션 없음 / 연타해도 안 깨짐 / 색은 CSS 변수 한 곳에서 변경
2. **AI 활용 내역**: Claude Code / 아래 프롬프트 / `docs/screenshots/home-v1.jpg`
   ```
   phoU 앱의 '홈' 화면 하나만 만들어줘. (규칙은 AGENTS.md)
   · 사용자: 모임·여행 뒤 친구와 사진을 나누려는 20-30대, 공유 앨범 4개가 있는 기존 유저
   · 화면 요소: 상단 작은 회색 보조 문구 + 큰 굵은 문구 "친구와 사진을 공유해볼까요?", 알림 벨 /
     내 앨범 2열 카드(대표 사진 자리, 이름, 날짜, 멤버 수) / 하단 탭바 3칸: 앨범 / ＋ 새 앨범 / 내 정보
   · 상태: 로딩 / 비어 있음(앨범 0개) / 완료(새 앨범 직후 NEW 표시)
   · 동작: 카드 → 공유된 앨범 보기, ＋ → 앨범 만들기 예정이니 지금은 안내 문구만. 내 정보 → "준비 중인 기능이에요"
   · 디자인: AGENTS.md 미니멀 흑백. Clutter 홈처럼 큰 질문형 문구가 주인공, 카드는 회색 면+얇은 테두리, 탭바는 테두리 있는 알약
   · 하지 말 것: 사진 대신 회색 박스. 실제 사람 이름 금지.
   지금은 이 화면만 만들고 이후 과정 결정할게. 다른 화면은 만들지 마.
   ```
3. **판단**: AI가 프롬프트 밖에서 정한 것 — 보조 문구 내용("이번 주말에 찍은 사진 36장이 그대로 있어요"), 빈 상태의 "새 앨범 만들기" 버튼, 알림 벨도 "준비 중" 안내. (받아들일지 검토 필요)
4. **검증**: WebKit 자동 캡처로 로딩·기본·빈 상태·완료·375px 확인. 스크립트로 Tab 순서(알림 → 카드 4개 → 탭바 3개), 최저 명도대비 4.80:1(카드 날짜 글씨), 16px 미만 본문 없음, 카드 5연타 시 토스트 1개, 가로 넘침 없음, CSS 변수 밖 색 하드코딩 없음 → 수용 기준 6개 모두 통과
5. **윤리 점검**: 앨범 이름은 상황 이름만, 사람 이름 없음. 코드 전체 AI 생성
